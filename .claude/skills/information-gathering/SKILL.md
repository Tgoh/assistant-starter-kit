# Information gathering

Filling the **known** gaps in `subjects/`: the ones marked `?`.

## What it's for

The register can only anticipate what it knows about. A renewal date never
written down can't be raised. This turns unknowns into facts a few at a time, so
it never becomes a data-entry session nobody wants to sit through.

## Steps

1. **Look before asking.** Check the subject file, and run `/mail-sweep` for
   anything a document would answer: policy schedules, renewal notices,
   statements. Asking something a search could answer wastes the expensive
   part, which is the principal's attention.
2. Pick **one domain**. Ask **5–8 questions**, phrased so they can be answered
   from memory or waved off.
   - **A blocked answer never holds the round.** Leave its `?` with the
     condition beside it and move on.
   - **Work out what else the domain should know**, not only the `?` marks
     already there: what would the register need to anticipate the next
     renewal, failure or deadline here? Add a `?` wherever that's missing.
3. Say partial answers are fine. **"I'd have to check" is a real answer**: it
   locates a paperwork gap.
4. Write answers straight into the subject file. Replace the `?`, don't append.
5. Derive what the new facts imply. A date or an interval becomes a row; the
   reason it matters stays beside the fact. **This is the step that produces
   the value.**

## What failure looks like

An audit. Twenty questions and a quiet resolution never to do it again. Ask
fewer than feels sufficient; the routine repeats.

## What this is not

Not `/brainstorm`, which finds gaps nobody has noticed yet. Kept apart, because
merged, the open-ended half always loses to the concrete half.
